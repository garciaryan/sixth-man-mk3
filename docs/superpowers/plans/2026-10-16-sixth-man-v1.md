# Sixth Man v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A league-members-only web app that ranks and compares Yahoo Fantasy NBA players using one league's point
values, over Season / L7 / L14 / L30 windows, from a nightly-synced SQLite store of per-game stats.

**Architecture:** Next.js App Router on one Fly machine. Sign in with Yahoo (OAuth 2.0 + OpenID) gated to managers
of `LEAGUE_KEY`. The admin's Yahoo connection drives a resumable per-date sync into SQLite. Pages read only SQLite,
and fantasy points are computed at read time by pure functions.

**Tech Stack:** Next.js 15, React 19, TypeScript 5, `node:sqlite`, Node 24, Node's built-in test runner
(`node --experimental-strip-types --test`), GitHub Actions, Fly.io. No other runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-10-16-sixth-man-design.md`

**Reference implementation:** `~/Projects/mint-condition`. Tasks that say "port from mint-condition" mean: copy the
named file, rename `mc_`/`mint` identifiers to `sm_`/`sixth`, and drop anything about Discogs or passwords.

## Global Constraints

- Runtime dependencies: `next`, `react`, `react-dom` only. Dev: `typescript`, `@types/node`, `@types/react`.
- Node 24 (`engines.node: ">=24"`), ESM (`"type": "module"`), relative imports with `.ts` extensions.
- Only one Fly machine, ever. SQLite file: `${DATA_DIR ?? "./data"}/sixth.db`.
- Yahoo tokens and secrets never reach the browser. All Yahoo calls happen server-side.
- Yahoo endpoints: authorize `https://api.login.yahoo.com/oauth2/request_auth`, token
  `https://api.login.yahoo.com/oauth2/get_token` (HTTP Basic client auth), userinfo
  `https://api.login.yahoo.com/openid/v1/userinfo` (`sub` = Yahoo GUID), API base
  `https://fantasysports.yahooapis.com/fantasy/v2`, always with `format=json`.
- OAuth redirect URI: `${APP_URL}/api/auth/callback`. Scopes: `openid fspt-r`.
- Throttle: at most 1 Yahoo request per second. Retries: 3 tries on 429/5xx with backoff 2 s, 4 s.
- Player batches: 25 `player_keys` per request.
- Session cookie: `sm_session`, HMAC-signed, 30 days, `httpOnly`, `secure` in production, `sameSite=lax`.
- Membership re-check after 24 hours (`users.checked_at`).
- Service-token refresh when under 5 minutes remain.
- "Yesterday" and all window dates are computed in `America/New_York`. Windows end yesterday, inclusive:
  L7 = yesterday−6 … yesterday, L14 = −13, L30 = −29; Season = `league_settings.start_date` … yesterday.
- A player "played" on a date when at least one of their stat values that day is nonzero.
- Compare page accepts 2–4 player keys.
- Cron: GitHub Actions `0 10 * * *` → `POST ${APP_URL}/api/sync`, `Authorization: Bearer ${SYNC_TOKEN}`.

## Review Focus

- **Server timezone vs. game dates:** the Fly machine runs in UTC, so at 02:00 UTC "yesterday" in UTC is still
  "today" in New York. `yesterday(now)` must use `America/New_York` (test in Task 2).
- **Yahoo's `"-"` and empty stat values:** for a player who didn't play, Yahoo returns `"-"` or `""`. These must
  parse to 0 and never become `NaN` in totals (test in Task 7).
- **Zero games in a window:** a player with GP 0 in L7 must show FP/G as `null` (rendered "—") and sort last, never
  `NaN` or `Infinity` (tests in Tasks 2 and 10).
- **Cron and catch-up at the same time:** a cron request arriving while a catch-up sync runs must not start a second
  sync or double-write a date. It returns `{ started: false, running: true }` (test in Task 9).
- **Bad compare URLs:** `/compare?p=` with 1, 5, duplicate or unknown keys must render a helpful message, not crash
  (test in Task 12).
